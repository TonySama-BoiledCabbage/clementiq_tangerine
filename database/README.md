# Database

- **Schema migrations** live with the backend in `services/api/alembic/` (`0001_initial_schema.py`, autogenerated from `clementiq/models.py`). Run them with `python -m clementiq.cli migrate` (`alembic upgrade head`). The `migrations/` folder here is intentionally empty; Alembic is the single source of truth.
- **Tiger Data / TimescaleDB objects** live in `timescale/001_hypertables.sql`: hypertables, the `txn_daily` and `txn_monthly` continuous aggregates, and refresh and compression policies. Apply them with `python -m clementiq.cli timescale` after the import.
- **Seed / import:** `python -m clementiq.cli import [--force] [--only loans] [--skip transactions]` loads the nine Tangerine CSVs from `data/`, reading `.csv` or `.csv.gz`. It produces a per-dataset quality report (visible at `/admin`) and rebuilds the derived `account_baselines` table. No synthetic customer records are ever seeded; the only synthetic rows are the test fixtures in `services/api/tests/fixture_data.py`, which never touch the app database.
- **Benchmark:** `python -m clementiq.cli benchmark` measures raw versus continuous-aggregate query timings and writes them to `docs/benchmarks/tiger_data_benchmark.json`.
